# نموذج التهديد — AlAdil Cybersecurity

يغطّي هذا المستند نموذج **STRIDE** للخادم والعميل، ثم مراجعة **OWASP API
Security Top 10 (2023)** لواجهات `server/app/api` مع الإصلاحات المطبَّقة.

مبني على مهارتَي `stride-threat-modeling` و `api-security-review`.

---

## 1) مخطط النظام والحدود الموثوقة

```
[متصفح المشرف] --HTTPS/JWT--> [خادم FastAPI] --SQLAlchemy--> [قاعدة بيانات SQLite/Postgres]
                                    ^                               (EncryptedString لحقول حسّاسة)
                                    |
                           --X-License-Key (Ed25519)--
                                    |
[عميل/Agent على جهاز العميل] -- يفحص الشبكة المحلية (قراءة فقط) --> [أجهزة الشبكة]
```

حدود الثقة (حيث يتغيّر السياق/الصلاحية):
- المتصفح ↔ الخادم (مصادقة JWT).
- العميل ↔ الخادم (مصادقة بمفتاح ترخيص موقَّع).
- الخادم ↔ قاعدة البيانات (تشفير الحقول الحسّاسة عند السكون).
- العميل ↔ أجهزة الشبكة (بوابة تفويض للنطاقات الخارجية).

## 2) تهديدات STRIDE

| العنصر | الفئة | التهديد | التخفيف المطبَّق |
|---|---|---|---|
| مصادقة المشرف (JWT) | **S**poofing | انتحال جلسة مشرف | JWT HS256 بسرّ عشوائي يُولَّد محليًا (`config.py`)، لا قيمة افتراضية مكشوفة |
| تقرير الفحص | **T**ampering | تزوير/تعديل تقرير | توقيع Ed25519 لكل تقرير (`ScanReportRecord`) + `/verify` |
| سجل التدقيق | **R**epudiation | إنكار/حذف سطر | سلسلة تجزئة (`shared/integrity.py`) تكشف الحذف/التعديل |
| حقول قاعدة البيانات | **I**nfo disclosure | تسريب مفاتيح التراخيص | `EncryptedString` (Fernet/AES) + المفاتيح خارج git (`secrets/`, `data/`) |
| تسجيل الدخول | **D**oS | تخمين كلمة المرور (brute-force) | **توصية**: إضافة حدّ معدّل (rate limit)؛ يُسجَّل كل فشل في سلسلة الأحداث |
| واجهات الأجهزة | **E**levation | وصول غير مصرَّح لبيانات | `get_current_user` على كل واجهة؛ التراخيص/الإصدار للمشرف فقط (`is_admin`) |
| مفتاح التوقيع الخاص | **I**nfo disclosure | سرقة مفتاح الخادم | يُخزَّن في `data/` المستبعد من git؛ **توصية**: نقله لمخزن مفاتيح/HSM في الإنتاج |
| العميل ↔ شبكة خارجية | **E**levation | فحص نطاق غير مُصرَّح | بوابة تفويض إلزامية (`authorization_gate`) + سجل موقَّع |

## 3) مراجعة OWASP API Security Top 10 (2023)

| # | الفئة | الحالة | ملاحظة/إصلاح |
|---|---|---|---|
| API1 | BOLA (صلاحية الكائن) | **مقبول للتصميم** | أداة مالك مفردة: كل مستخدم مُصادَق هو المالك؛ لا عزل متعدد المستأجرين لازم |
| API2 | ضعف المصادقة | **جيد** | سرّ JWT عشوائي، كلمة المرور bcrypt، تغيير كلمة المرور يتطلب الحالية |
| API3 | BOPA (كشف مفرط) | **جيد** | المُسلسِلات تعرض حقولًا محدَّدة؛ مفتاح الترخيص الكامل للمشرف فقط |
| API4 | استهلاك الموارد | **توصية** | لا حدّ معدّل على `/login` و `/scans/report` — يُنصح بإضافة rate limit |
| API5 | BFLA (صلاحية الوظيفة) | **جيد** | التراخيص/الإصدار محميّة بـ `is_admin`؛ البقية تتطلب مصادقة |
| API6 | تدفّقات العمل الحسّاسة | **غير منطبق** | لا شراء/حجز آلي |
| API7 | SSRF | **جيد** | لا جلب URL يتحكم به المستخدم على الخادم؛ NVD عبر رابط ثابت |
| API8 | سوء الإعداد/الحقن | **أُصلح** | CORS مقصور على localhost؛ **إصلاح**: التحقق من صحة `ip_address` في `/block-command` قبل إدراجه في أمر PowerShell (منع حقن أوامر عند تنفيذ المستخدم للأمر) |
| API9 | إدارة المخزون | **جيد** | الواجهات محصورة ومسجَّلة في `main.py`؛ لا نقاط ظلّ معروفة |
| API10 | استهلاك آمن | **جيد** | مدخلات JSON عبر Pydantic (تحقّق صارم)؛ لا deserialization غير آمن |

### إصلاحات مطبَّقة في هذه المراجعة
1. **API8/حقن**: `/api/devices/{id}/block-command` كان يُدرج `device.ip_address`
   الخام في أمر PowerShell يُعرض للمستخدم لتنفيذه. جهاز مُسيطَر عليه قد
   يُبلّغ عنوانًا خبيثًا يحقن أوامر إضافية في طرفية المستخدم. **الإصلاح**:
   التحقق أن القيمة عنوان IP صالح (`ipaddress.ip_address`) قبل بناء الأمر.

### توصيات مستقبلية (موثّقة، غير حرجة لأداة مالك محلية)
- إضافة حدّ معدّل (rate limiting) على `/login` و `/scans/report`.
- نقل مفتاح التوقيع الخاص إلى مخزن مفاتيح نظام التشغيل أو HSM في الإنتاج.
- تفعيل المصادقة متعددة العوامل (2FA) لحساب المشرف — انظر مهارة
  `two-factor-authentication-best-practices`.
